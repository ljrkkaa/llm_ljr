# An End-to-end Planning Framework with Agentic LLMs and PDDL

## 1. 引言：人工智能规划领域的神经符号融合范式

在人工智能（AI）发展的历史长河中，规划（Planning）始终被视为智能行为的基石。从机器人执行复杂的装配任务，到物流网络的动态调度，再到数字助理协助人类安排日程，规划能力——即从高层目标推导出具体的、有序的行动序列——是区分简单自动化与真正智能的关键指标 ^1^。长期以来，自动规划领域一直由符号人工智能（Symbolic AI）主导，特别是基于斯坦福研究所问题求解器（STRIPS）和规划领域定义语言（PDDL）的形式化方法。这些方法以其逻辑的严密性、解的正确性保证以及对最优性的追求而著称 ^1^。然而，符号规划面临着著名的“知识获取瓶颈”：它要求领域专家手动编写极其精确、毫无歧义的领域模型（Domain Model）和问题描述（Problem Description）。这种对形式化输入的苛刻要求，极大地限制了自动规划技术在充满不确定性和模糊性的人类现实世界中的普及。

近年来，随着以 GPT-4 和 GPT-5 系列为代表的大型语言模型（LLMs）的崛起，人工智能的交互范式发生了翻天覆地的变化。LLM 展现出了惊人的自然语言理解能力和代码生成能力，能够轻松处理模糊、不完整甚至隐含的人类指令 ^3^。然而，当应用于长程规划任务时，LLM 的局限性暴露无遗。作为本质上的概率预测引擎，LLM 缺乏内部的世界状态模拟器，这导致它们在生成长序列行动时经常出现“幻觉”（Hallucination），即生成看似合理但实际上违反物理约束或逻辑规则的步骤 ^1^。研究表明，即便是在 GPT-5-mini 这样先进的模型中，直接生成长程规划的成功率依然不尽如人意，尤其是在涉及复杂递归逻辑（如汉诺塔问题）或严格资源约束（如物流问题）的场景下 ^1^。

为了解决这一“语言灵活性”与“逻辑严密性”之间的矛盾，牛津大学的 Emanuele La Malfa 等研究团队于 2025 年 12 月提出了一种全新的神经符号（Neuro-symbolic）架构——“基于代理式 LLM 和 PDDL 的端到端规划框架”（An End-to-end Planning Framework with Agentic LLMs and PDDL）^1^。该框架不仅代表了自动规划领域的一次重大飞跃，更展示了代理式人工智能（Agentic AI）如何通过动态编排、迭代细化和外部工具调用，来实现超越单一模型能力的复杂推理。本报告将对该框架进行详尽的解构与分析，探讨其架构设计、工作机制、实验表现以及对未来人工智能系统的深远影响。

## 2. 理论背景与技术基础

### 2.1 自动规划与 PDDL 的形式化严谨性

自动规划的核心在于寻找一个动作序列，使得系统从初始状态转移到目标状态。PDDL（Planning Domain Definition Language）自 1998 年提出以来，已成为该领域的通用标准 ^1^。PDDL 将规划问题解耦为两个核心文件：

1. **领域文件（Domain File）：** 定义了环境中的对象类型（Types）、谓词（Predicates）以及可执行的动作（Actions）。每个动作都包含先决条件（Preconditions）和效果（Effects），构成了世界的“物理法则”。
2. **问题文件（Problem File）：** 描述了具体的任务实例，包括具体的对象（Objects）、初始状态（Initial State）和目标状态（Goal State）。

PDDL 的优势在于其不可动摇的逻辑基础。一旦问题被正确编码，现代规划器（如 Fast Downward、LPG、POPF）就能利用启发式搜索算法（如 A*）找到保证正确甚至最优的解 ^1^。然而，PDDL 的语法极其严格，任何括号的遗漏、变量类型的错误或谓词定义的冲突都会导致规划器报错并拒绝执行。这种“零容忍”的特性正是 LLM 直接生成 PDDL 时的最大障碍——语言模型倾向于生成“差不多正确”的文本，但在形式化逻辑中，“差不多”等同于“错误”。

### 2.2 大型语言模型的规划困境

大型语言模型在处理规划任务时面临着根本性的架构限制。由于其自回归（Autoregressive）的生成机制，LLM 本质上是在进行基于概率的 token 预测，而非基于状态空间的搜索。这意味着模型无法在生成步骤 **$t$** 时有效地“预见”步骤 **$t+10$** 的状态约束，导致生成的计划往往在后半段出现逻辑崩塌 ^1^。此外，LLM 难以处理“硬约束”（Hard Constraints）。例如，在物流问题中，如果卡车已经在地点 A，它就不能同时出现在地点 B。虽然 LLM 在文本层面上理解这一点，但在长序列生成中，它经常会“遗忘”这一状态，导致物体瞬移或资源凭空产生。

### 2.3 代理式人工智能（Agentic AI）的兴起

为了克服单一模型的局限，AI 研究正转向代理式系统（Agentic Systems）。与静态的问答模型不同，代理式系统具备使用工具、维护记忆、分解任务以及自我纠错的能力 ^1^。在 La Malfa 等人的框架中，这一理念被推向了极致。系统不再依赖单一的 LLM 完成所有工作，而是构建了一个由“编排器”（Orchestrator）领导的多智能体协作网络。编排器动态地生成工作流，调用专门负责语法修复、逻辑检查、约束验证的子代理，形成了一个具有自我进化能力的规划工厂 ^1^。这种设计灵感来源于 ReAct（Reason + Act）范式，但通过引入形式化验证器（Validators）作为反馈源，极大地增强了系统的鲁棒性。

## 3. 端到端代理规划框架的系统架构

该研究提出的框架是一个完全自动化的闭环系统，旨在弥合自然语言意图与形式化规划之间的鸿沟。其架构设计精妙地结合了 LLM 的语义理解能力与符号求解器的逻辑推理能力。

### 3.1 核心组件概览

| **组件名称**                | **核心功能描述**                                                   | **技术支撑**             |
| --------------------------------- | ------------------------------------------------------------------------ | ------------------------------ |
| **编排器 (Orchestrator)**   | 系统的“大脑”，负责解析用户意图，动态生成工作流，并根据反馈调度子代理。 | GPT-5-mini, Prompt Engineering |
| **JSON 中间表示层**         | 连接自然语言与 PDDL 的桥梁，结构化地存储环境、代理、目标和约束信息。     | JSON Schema, Structured Output |
| **PDDL 生成器**             | 将结构化的 JSON 数据转换为初始的 PDDL 领域和问题文件。                   | LLM-based Translation          |
| **代理式细化器 (Refiners)** | 一组专门化的子智能体，负责修复语法错误、逻辑漏洞和约束冲突。             | Multi-Agent Collaboration      |
| **符号求解器与验证器**      | 执行实际的规划搜索和有效性验证，提供客观的反馈日志。                     | Fast Downward, VAL, uVAL       |
| **自然语言回译器**          | 将符号化的规划结果翻译回人类可读的自然语言。                             | LLM-based Summarization        |

### 3.2 编排器（Orchestrator）：动态工作流引擎

编排器是整个框架的控制中心。与以往采用静态角色分配的研究（如 Liu et al. 的 LLM+P）不同，本框架的编排器能够根据任务的实时状态动态创建多智能体工作流 1。

当接收到用户的自然语言指令时，编排器首先进行需求分析。如果指令存在歧义或矛盾（例如，“我想在 8 点前到达，但 9 点才出发”），编排器有能力调用澄清代理（Clarifier）与用户交互（尽管在实验中为实现全自动化，该功能通常被设为隐式处理）1。

编排器的决策逻辑基于详尽的系统提示词（System Prompt）。如附录所示，编排器会接收当前所有的规划工件（Artefacts），包括 PDDL 代码、求解器日志、验证器报错信息以及历史操作记录。基于这些信息，编排器从可用的代理池中选择最合适的下一个代理进行干预 1。

### 3.3 JSON 中间表示层：结构化的语义桥梁

直接从自然语言生成 PDDL 是一项高风险操作。为了降低难度，该框架引入了 JSON 作为中间表示层 ^1^。JSON 的引入具有双重战略意义：

1. **异构数据的统一：** 规划任务通常包含环境信息（如地图拓扑）、代理信息（如机器人能力）、目标（如“把箱子搬到 B”）和约束（如“电量不能低于 10%”）。JSON 能够以键值对的形式清晰地组织这些异构数据，消除了自然语言叙述中的线性干扰。
2. **训练数据的契合：** 现代 LLM（如 GPT-5）在预训练阶段接触了海量的 JSON 数据，因此在生成和解析 JSON 结构方面表现出极高的稳定性和准确性 ^1^。

研究展示的 JSON 结构极其详尽。以“日历调度”任务为例，JSON 文件明确区分了“代理”（agents）、“环境”（environment）和“工作流”（workflow）。每个代理的条目下不仅包含其“目标”（goal），还包含“私有信息”（private_information，如具体的忙碌时间段）。这种显式的结构化迫使模型在生成 PDDL 之前，必须先理清各个实体之间的关系和约束，从而大大减少了逻辑幻觉的发生 ^1^。

### 3.4 代理式细化循环（The Refinement Loop）

这是框架中最具创新性的部分。系统并不期望一次性生成完美的 PDDL 代码，而是通过一个迭代的“生成-验证-修复”循环来逼近正确解。这个循环由一系列专门化的代理驱动，每个代理都是一个经过特定指令微调或提示工程优化的 LLM 实例 ^1^。

#### 3.4.1 关键代理及其功能解析

* **FastDownwardsAdapter（求解器适配器）：** 即使 PDDL 代码在语法上是通用的，不同的求解器（如 Fast Downward）也可能对某些特性（如条件效果或派生谓词）有特定的支持限制。该代理负责调整 PDDL 代码，使其符合特定目标求解器的语法偏好，确保代码能够被正确解析 ^1^。
* **SyntaxPDDL（语法修复专家）：** 这是实验中被调用频率最高的代理。它专门处理由验证器（VAL）报告的语法错误，如括号不匹配、未定义的参数类型或谓词声明错误。鉴于 LLM 在处理长代码时的“注意力漂移”问题，该代理的存在至关重要 ^1^。
* **DeepThinkPDDL（深度逻辑思考者）：** 该代理超越了简单的语法检查，深入分析 PDDL 模型的语义逻辑。它负责识别约束、目标和最终计划之间的深层不一致性。例如，如果目标是“所有包裹都在 B”，但生成的动作序列没有移动包裹的步骤，DeepThinkPDDL 就会介入 ^1^。
* **DeepThinkConstraints（约束一致性检查）：** 专门用于验证自然语言提示中的约束是否被正确编码到 PDDL 中。例如，用户要求“不要在晚上 8 点后乘坐火车”，该代理会检查 PDDL 的动作前提（Precondition）中是否包含相应的时间检查逻辑 ^1^。
* **TemporalConsistency（时间一致性校验）：** 在涉及时间安排的任务（如会议调度）中，LLM 经常在时间计算上出错（例如，认为 14:00 到 15:00 的会议可以在 14:30 开始的空档中进行）。该代理专门负责审核时间逻辑，确保所有事件在时间轴上是不冲突且连续的 ^1^。

### 3.5 求解与回译

经过多轮细化后，验证通过的 PDDL 模型被送入外部求解器。求解器利用高效的搜索算法（如 **$A^*$**）在庞大的状态空间中寻找最优解。生成的解（Plan）是一个符号化的动作序列（如 `(move truck1 cityA cityB)`）。最后，`AgentNaturalLanguage` 将这个枯燥的符号序列翻译成流畅的自然语言文本，呈现给用户。这一步不仅提高了可读性，还通过自然语言的逻辑连贯性提供了最后一道“合理性检查” ^1^。

## 4. 实验评估与结果分析

为了全面验证框架的有效性，研究团队在多个具有挑战性的基准测试集上进行了广泛的实验，并与直接使用 GPT-5-mini 进行规划的基线方法进行了对比。实验不仅关注解的正确率（Accuracy），还关注解的质量（Cost Optimality）和系统的鲁棒性。

### 4.1 基准测试集介绍

* **Google Natural Plan Benchmark:** 由 Zheng 等人于 2024 年提出的基准，包含日历调度（Calendar Scheduling）、会议规划（Meeting Planning）和旅行规划（Trip Planning）三个子任务。这些任务贴近现实生活，强调对自然语言约束的理解和时间管理能力 ^1^。
* **PlanBench:** 由 Valmeekam 等人提出的经典规划基准，涵盖了积木世界（Blocksworld）、物流（Logistics）和仓库（Depots）等领域。特别是包含了“混淆”（Obfuscated）版本的领域，即将动作名称替换为无意义的字符串（如将`unstack` 替换为`op1`），以测试模型是否真正掌握了逻辑规则，而非仅仅依赖训练数据中的语义联想 ^1^。
* **汉诺塔（Tower of Hanoi）：** 这是一个经典的递归问题，要求将一堆圆盘从一根柱子移动到另一根，且大盘不能压在小盘上。由于其解法步骤随盘数指数级增长（**$2^n-1$**），这对 LLM 的长程推理能力构成了极大的挑战 ^1^。

### 4.2 实验结果：超越单一模型的极限

实验结果表明，引入 PDDL 层的代理式框架在所有任务上都显著优于直接使用 GPT-5-mini。

#### 4.2.1 Google Natural Plan 表现

| **任务类型** | **GPT-5-mini 准确率** | **代理式框架准确率** | **提升幅度** |
| ------------------ | --------------------------- | -------------------------- | ------------------ |
| **日历调度** | ~50%                        | **~80%**             | **+30%**     |
| **会议规划** | ~24%                        | **~51%**             | **+27%**     |
| **旅行规划** | ~38%                        | **~45%**             | +7%                |

数据来源：基于 ^1^ 图 3 的视觉估算与文本描述。

在**日历调度** 和**会议规划** 任务中，框架展现了巨大的优势。这是因为这类问题本质上是约束满足问题（Constraint Satisfaction Problems），涉及大量的时间冲突检测。LLM 直接生成时容易忽略微小的时间重叠，而 PDDL 求解器则能精确地处理这些硬约束 ^1^。旅行规划的提升相对较小，这可能与该数据集本身存在的歧义（Ground Truth 错误）有关，研究团队发现原始数据集在计算旅行时间时存在逻辑不一致，这在一定程度上干扰了精确规划器的表现 ^1^。

#### 4.2.2 PlanBench 与逻辑推理表现

| **任务类型**               | **GPT-5-mini 准确率** | **代理式框架准确率** | **性能分析**                                         |
| -------------------------------- | --------------------------- | -------------------------- | ---------------------------------------------------------- |
| **物流 (Logistics)**       | ~76%                        | **100%**             | 完美解决，体现了求解器在路径规划上的绝对优势。             |
| **积木世界 (Blocksworld)** | ~50%                        | **97%**              | 在涉及堆叠顺序和空间关系的推理上，符号方法远超概率模型。   |
| **混淆物流 (Obfuscated)**  | 极低                        | **显著高**           | 证明框架依赖的是逻辑规则而非语义联想，具有真正的推理能力。 |

特别是在**混淆领域** （Obfuscated Deceptive Logistics）中，GPT-5-mini 的表现大幅下降，因为它无法利用“卡车”、“驾驶”等词汇的语义先验知识。而代理式框架通过解析逻辑结构生成 PDDL，对符号的名称不敏感，因此依然能保持极高的准确率 ^1^。

#### 4.2.3 汉诺塔（Tower of Hanoi）的突破

汉诺塔测试是验证该框架递归推理能力的试金石。

* **4 盘实例：** GPT-5-mini 准确率为 92%，代理式框架为 100%。
* **7 盘实例：** GPT-5-mini 的准确率跌至**0%** 。这是因为 7 盘汉诺塔的最优解需要 127 步，LLM 几乎不可能在没有幻觉的情况下准确生成如此长的序列。
* **代理式框架表现：** 在 7 盘实例上达到了**90%** 的准确率。一旦 PDDL 领域规则（大盘不能压小盘）被正确生成，外部求解器可以毫秒级地生成 127 步甚至更长的最优解。这生动地展示了“推理”与“计算”分离的巨大价值 ^1^。

### 4.3 成本优化与效率

除了正确率，该框架还显著提升了计划的质量。通过在 Fast Downward 求解器中启用 $A^*$ 算法并配置成本最小化目标，框架生成的计划在**总成本（Plan Cost）**上平均降低了 45.8% 1。

例如，在旅行规划中，LLM 可能生成一个绕路的行程，虽然可行但不经济。而 PDDL 求解器会遍历状态空间，找到距离最短或耗时最少的路径。这在物流和供应链管理等对成本敏感的实际应用中具有决定性意义。

### 4.4 代理行为分析：系统的“自我意识”

研究团队深入分析了编排器在不同任务中调用代理的频率，揭示了任务特性的差异 ^9^。

* **语法修复的主导地位：**`SyntaxPDDL` 是被调用最频繁的代理，这证实了生成符合严格语法的代码依然是 LLM 的主要短板。
* **时间敏感性：** 在日历调度任务中，`TemporalConsistency` 代理被频繁调用，说明编排器“意识”到了任务的时间属性，并主动部署专家代理进行检查。
* **适配器的必要性：**`FastDownwardsAdapter` 的高频使用表明，通用的 PDDL 知识往往不足以应对特定求解器的工程化要求，专门的适配层是必不可少的 ^1^。

## 5. 讨论与批判性分析

### 5.1 解决“幻觉”与歧义的机制

本研究最深刻的洞见之一在于重新定义了 AI 处理歧义的方式。在传统规划中，歧义是致命的；而在纯 LLM 生成中，歧义往往被“脑补”成错误的假设。该框架利用编排器作为“歧义过滤器”。在生成 JSON 和 PDDL 的过程中，系统被迫将模糊的自然语言转化为精确的符号。如果约束存在矛盾，`DeepThinkPDDL` 会在规划开始前就侦测到并报错，从而从源头上截断了幻觉的产生路径 ^1^。这使得生成的计划具有“构造正确性”（Correctness by Construction）。

### 5.2 代理系统的“脆弱性”（Brittleness）

尽管表现优异，作者也坦诚地指出了系统的脆弱性 ^1^。编排器的决策高度依赖于提示词的微小变化（Prompt Sensitivity）。例如，仅仅是引入一个检查时间约束的代理，可能会导致编排器在不相关的任务中也过度调用该代理，造成资源浪费。这种现象表明，随着 AI 系统向多智能体架构演进，传统的“提示工程”正在演变为更复杂的“编排工程”或“认知架构设计”，如何保证元控制器（Meta-Controller）的稳定性将是未来的研究热点。

### 5.3 评估方法的挑战：LLM-as-a-Judge 的局限

报告对当前流行的“LLM 作为裁判”（LLM-as-a-judge）的评估方法提出了严厉批评。如果一个任务（如 7 盘汉诺塔）难到 GPT-5 无法解决，那么让 GPT-5（甚至 GPT-4）去判断另一个模型生成的解是否正确，其结果是不可信的 ^1^。该框架提倡回归客观标准——**代码验证** 。PDDL 验证器（VAL）提供了一个绝对的真理标准：如果计划通过了物理模拟的验证，它就是正确的。这种基于逻辑模拟的评估远比基于语义相似度的评估更为可靠。

### 5.4 与相关工作的对比

与 Liu 等人提出的 LLM+P 相比，本框架最大的优势在于动态性和闭环反馈。LLM+P 通常采用“一次性翻译”的静态流水线，一旦翻译出错，流程即告失败。而本框架的代理式细化循环允许系统从错误中恢复，体现了更高级的智能形式 1。

与 Wu 等人的 CoBlock 相比，本框架强调的是代理与求解器的协作，而非单纯的代理与代理协作。在涉及物理约束的场景下，引入求解器作为“物理引擎”比单纯依靠两个 LLM 互相“聊天”要可靠得多 1。

## 6. 结论与展望

“基于代理式 LLM 和 PDDL 的端到端规划框架”代表了神经符号人工智能的一次重要融合。它并没有试图用神经网络取代符号推理，而是将两者放置在最擅长的位置：LLM 负责处理人类语言的模糊性和意图的推断，而符号求解器负责处理逻辑的严密性和长程的因果推演。

本研究的核心贡献总结如下：

1. **架构创新：** 提出了首个集成动态编排、JSON 中间态、迭代细化和符号求解的端到端规划架构。
2. **性能突破：** 在 Google Natural Plan 和 PlanBench 等基准上，相对于 GPT-5-mini 取得了 30%-40% 的准确率提升，并在汉诺塔等递归难题上实现了从 0 到 90% 的质变。
3. **工程实践：** 通过开源代码和 Web 界面（Planning Copilot），降低了高级规划技术的使用门槛，使得非专家用户也能利用工业级的 PDDL 求解器 ^1^。

未来展望：

随着 AI 向物理世界（Embodied AI）延伸，这种框架的应用前景广阔。未来的研究可以探索将该架构扩展到多模态领域（例如，让机器人看图生成 PDDL），或者引入强化学习来优化编排器的决策策略，使其在面对新任务时能更高效地选择代理组合 1。此外，解决基准测试集的质量问题，建立更严谨、无歧义的评估标准，也是推动该领域发展的当务之急。

这一研究不仅解决了当前 LLM 在规划任务上的痛点，更预示了未来人工智能系统的一个重要发展方向：**System 1（直觉/LLM）与 System 2（逻辑/Solver）的深度协同** 。
