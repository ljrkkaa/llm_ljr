# DELTA: Decomposed Efficient Long-Term Robot Task Planning using Large Language Models

## 执行摘要

随着人工智能技术的飞速发展，移动机器人正逐渐从结构化的工业环境走向非结构化的家庭与办公场景。在这些复杂环境中，机器人不仅需要具备基本的移动与避障能力，更需要能够理解复杂的自然语言指令，并将其转化为长周期的、包含多个步骤的任务序列。这一领域被称为长期任务规划（Long-Term Task Planning）。传统的符号规划方法（如 PDDL）虽然逻辑严密，但在面对非结构化环境时，往往因为状态空间爆炸而难以求解；而新兴的大型语言模型（LLMs）虽然具备强大的语义理解和常识推理能力，却深受“幻觉”（Hallucination）困扰，生成的计划常缺乏物理可行性。

本报告对发表于 IEEE 机器人与自动化国际会议（ICRA）2025 的前沿论文《DELTA: Decomposed Efficient Long-Term Robot Task Planning using Large Language Models》进行了全面且详尽的深度剖析。该研究提出了一种名为 DELTA 的创新神经符号框架，旨在通过深度融合 LLM 的语义智慧与经典规划器的逻辑严密性，解决机器人长期任务规划中的效率与可靠性难题。

DELTA 框架的核心创新在于引入了“3D 场景图”（3D Scene Graphs, SGs）作为环境的中间表征，并利用“场景图剪枝”（Scene Graph Pruning）和“自回归目标分解”（Autoregressive Goal Decomposition）两大策略，将原本不可解的复杂长视距问题转化为一系列可解的短视距子问题。

实证研究表明，在涉及数十个操作步骤的复杂任务（如房屋清洁、办公室布置）中，DELTA 展现出了压倒性的性能优势。与当前的 SOTA 方法（如 SayPlan）相比，DELTA 不仅将任务成功率从基线的 0%-54% 提升至 80%-100%，更将规划时间缩短了三个数量级（最高达 3000 倍）。这一突破性成果不仅验证了神经符号 AI 在机器人领域的巨大潜力，更为服务机器人的智能化落地提供了可行的技术路径。

本报告将从研究背景、理论基础、技术架构、实验分析、前沿对比及未来展望等维度，对 DELTA 进行全方位的解读与评测。

## 1. 引言

### 1.1 机器人任务规划的演进与挑战

机器人任务与运动规划（Task and Motion Planning, TAMP）一直是机器人学皇冠上的明珠。其核心目标是让机器人根据高级指令，自主生成一系列低级动作序列以改变环境状态。在过去的几十年里，这一领域经历了从纯符号规划到基于学习的规划的演变。

传统的**符号规划** （Symbolic Planning），如基于斯坦福研究所问题求解器（STRIPS）或规划域定义语言（PDDL）的方法，依赖于人工定义的规则和严格的逻辑推演。它们具有数学上的完备性和正确性保证，能够确保生成的计划在逻辑上是通畅的。然而，符号规划面临着著名的“知识获取瓶颈”——需要专家耗费大量精力手工编写领域知识，且难以适应开放世界的变化。此外，随着环境中物体数量的增加，符号规划的搜索空间呈指数级增长，导致计算上的不可行性（Computational Intractability）^1^。

近年来，**大型语言模型** （Large Language Models, LLMs）的爆发为 TAMP 带来了新的曙光。LLMs 蕴含了海量的互联网知识，能够理解“把牛奶放进冰箱”意味着“先打开冰箱门”，这种常识推理能力正是传统规划器所欠缺的。然而，直接将 LLM 用作规划器（LLM-As-Planner）已被证明存在严重缺陷。由于 LLM 本质上是基于概率的文本生成器，而非基于物理法则的模拟器，它们经常产生“幻觉”，生成诸如“穿过墙壁移动”或“在没有手的情况下抓取物体”等不可执行的计划 ^1^。

因此，如何结合两者的优势——利用 LLM 的常识进行“直觉”引导，利用经典规划器进行“逻辑”验证——成为了当前神经符号 AI（Neuro-Symbolic AI）的研究热点。DELTA 正是在这一背景下提出的解决方案。

### 1.2 DELTA 的研究动机与核心贡献

DELTA（Decomposed Efficient Long-Term TAsk planning）的研究动机直指当前 LLM 驱动的规划系统在处理**长期任务（Long-Term Tasks）**时的无力感。当任务步骤超过一定长度（例如 >10 步），LLM 的上下文窗口限制和推理漂移会导致计划不仅逻辑混乱，而且完全偏离初始目标。同时，现有的神经符号方法（如 LLM+P）在将非结构化环境转化为符号表示时，往往引入了过多的冗余信息，导致底层规划器超时。

针对这些痛点，DELTA 提出了以下核心贡献：

1. **基于场景图的语义接地** ：首次系统性地将 3D 场景图与 LLM 结合，利用图结构的高效性实现环境信息的快速检索与剪枝，解决了 LLM 输入过载和幻觉问题。
2. **自回归目标分解策略** ：提出了一种受人类认知启发的分解机制，将复杂的长目标拆解为子目标序列，使自动规划器只需解决局部问题，从而规避了组合爆炸。
3. **零样本/少样本泛化能力** ：通过精心设计的 Prompt Engineering，实现了在无需重新训练模型的情况下适应新领域（Unseen Domains）的能力。
4. **卓越的性能验证** ：在多个高难度基准测试中，证明了其在成功率和时间效率上对现有 SOTA 方法的全面超越 ^1^。

## 2. 理论基础与技术背景

为了深入理解 DELTA 的工作机理，必须首先剖析其赖以生存的三大理论支柱：形式化规划语言（PDDL）、3D 场景图（3DSGs）以及大型语言模型的推理机制。

### 2.1 形式化规划语言：PDDL 的复兴

规划域定义语言（Planning Domain Definition Language, PDDL）诞生于 1998 年，是国际规划大赛（IPC）的标准语言。在 DELTA 架构中，PDDL 扮演了“逻辑约束层”的角色。

一个典型的 PDDL 系统包含两个核心文件：

1. **Domain（域）文件** ：定义了物理世界的通用法则。它描述了对象类型（Type Hierarchy）、谓词（Predicates）以及动作图式（Action Schemas）。
   * *谓词* ：如`(at?agent?room)` 表示机器人在某个房间，`(clean?item)` 表示物品是干净的。
   * *动作* ：每个动作由参数、前置条件（Preconditions）和效果（Effects）组成。例如，执行`pick-up` 动作的前提是机器人手是空的且位于物体旁边，效果是机器人手不再空且持有该物体。这种严谨的定义确保了生成的计划在逻辑上是因果连贯的。
2. **Problem（问题）文件** ：定义了特定任务的具体实例。它列出了所有的对象实例（如`room1`,`apple1`），初始状态（Initial State）和目标状态（Goal State）。

DELTA 的巧妙之处在于，它不要求人类编写这些复杂的文件，而是利用 LLM 将自然语言自动翻译成 PDDL 代码。这利用了 LLM 强大的代码生成能力，同时利用 PDDL 求解器（如 Fast Downward）保证了解的正确性，形成互补 ^2^。

### 2.2 3D 场景图：从几何到语义的桥梁

机器人感知的传统输出通常是点云（Point Cloud）或体素网格（Voxel Grid）。这些表示包含了丰富的几何细节，但缺乏语义结构，对于任务规划而言过于低级且数据量庞大。

**3D 场景图（3D Scene Graphs, SGs）** 是一种分层的环境抽象表征。它将环境建模为一个有向图：

* **节点（Nodes）** ：代表环境中的实体，通常分为多层，如`Building` ->`Room` ->`Object`。每个节点不仅包含语义标签（如 "Kitchen"），还包含属性（如 "Bounding Box", "State: Open/Closed"）。
* **边（Edges）** ：代表实体间的关系，包括空间关系（"inside", "next_to"）和逻辑关系（"connected_to"）。

在 DELTA 中，场景图是连接机器人感知与 LLM 推理的关键桥梁。相比于直接输入图像（像素级）或点云（坐标级），场景图将环境压缩为 LLM 易于理解的文本化图结构（Textual Graph Representation）。这种高层抽象不仅极大地减少了输入 Token 的数量，还通过显式的语义关联帮助 LLM 更好地理解环境拓扑 ^1^。

### 2.3 大型语言模型的推理范式

DELTA 利用了 LLM 的**上下文学习（In-Context Learning）**能力，特别是** 单样本提示（One-Shot Prompting）** 。通过在 Prompt 中提供一个单一的、高质量的示例（如洗衣任务的 PDDL 定义），LLM 能够通过类比推理，将这种模式泛化到全新的领域（如组装电脑或清理房屋）。

此外，DELTA 实际上在架构层面实现了类似“思维链”（Chain-of-Thought, CoT）的效果。它没有让 LLM 直接输出最终答案，而是强迫 LLM 先生成域定义，再生成问题定义，最后分解目标。这种分步骤的生成过程显式地引导了模型的推理路径，大大降低了逻辑错误的概率。

## 3. DELTA 技术架构深度解析

DELTA 的系统架构是一个精心设计的流水线，包含五个紧密耦合的步骤。本节将详细剖析每一步的输入输出、算法逻辑及其背后的设计哲学。

![The system architecture of DELTA](https://delta-llm.github.io/static/images/delta_sys_overview.png)

### 3.1 步骤一：域生成 (Domain Generation) —— 构建物理法则

系统的第一步是建立规划的“宪法”。在这一阶段，DELTA 要求 LLM 根据自然语言的描述，生成 PDDL 域文件。

* **输入** ：自然语言描述的域知识（Domain Knowledge）。例如：“机器人可以在房间之间移动，可以抓取一个物体，如果手是空的。它还可以使用拖把拖地，但这会弄脏拖把。”
* **核心机制** ：Prompt 设计遵循“角色-示例-指令”（Role-Example-Instruction）结构。
  * *Role* ：你是一个 PDDL 生成专家。
  * *Example* ：提供一个完整的`Laundry` 域的自然语言描述及其对应的 PDDL 代码。这不仅展示了语法，还展示了如何将“把脏衣服放进洗衣机”这样的概念转化为`(put-in?item?container)` 动作。
  * *Instruction* ：针对新的任务描述，生成对应的 PDDL。
* **输出** ：`domain.pddl`。包含`:types`,`:predicates`,`:action` 等定义。
* **技术洞察** ：这一步实现了**零代码的领域适应** 。传统规划器在面对新环境（如从家庭变为工厂）时，需要专家重写代码。DELTA 允许普通用户通过自然语言定义新的动作逻辑（如定义一个新的`weld` 焊接动作），极大地降低了使用门槛 ^2^。

### 3.2 步骤二：场景图剪枝 (Scene Graph Pruning) —— 注意力聚焦机制

这是 DELTA 区别于基线模型（如 LLM+P）的关键创新。在真实世界中，一个家庭环境可能包含数百个物体。如果将所有物体都写入 PDDL 问题文件，规划器的搜索空间将变得巨大无比，导致求解超时。

* **输入** ：完整的场景图（Python 嵌套字典格式）+ 用户目标描述（如“把可乐罐扔掉”）。
* **算法逻辑** ：
  1. LLM 接收完整场景图的文本表示。
  2. LLM 分析用户目标，识别出其中的“关键实体”（Key Entities）。例如，对于“扔可乐罐”任务，关键实体是`Cola_Can`（目标物）和`Trash_Bin`（容器）。
  3. LLM 进一步推断“辅助实体”。例如，为了扔垃圾，机器人需要经过`Living_Room` 和`Kitchen`，因此这两个房间节点也是相关的。
  4. LLM 输出一个过滤后的列表，仅保留上述相关节点。
* **输出** ：修剪后的子场景图（Pruned SG）。
* **技术优势** ：
  * **计算效率** ：将规划问题的规模从**$N_{total}$** 降低到**$N_{relevant}$**，通常能减少 90% 以上的无关物体。
  * **抗干扰性** ：移除了无关物体（如“床”、“电视”），减少了 LLM 将这些物体错误地编入动作序列的风险（幻觉抑制）^1^。

### 3.3 步骤三：问题生成 (Problem Generation) —— 任务实例化

在此步骤，系统将修剪后的环境快照转换为 PDDL 问题实例。

* **输入** ：修剪后的场景图 + 用户目标描述 +`domain.pddl`（作为谓词参考）。
* **转换逻辑** ：
  * **初始状态映射（Init State Mapping）** ：遍历场景图的节点和边。
    * 节点属性`is_clean: True` -> 谓词`(clean item)`。
    * 边关系`connected(RoomA, RoomB)` -> 谓词`(connected RoomA RoomB)`。
  * **目标状态解析（Goal State Parsing）** ：LLM 将“把房子打扫干净”解析为一组逻辑状态，如`(and (in trash_bin cola_can) (clean floor))`。
* **输出** ：`problem.pddl`，包含`:objects`,`:init`,`:goal`。
* **关键点** ：LLM 必须严格使用`domain.pddl` 中定义的谓词，否则会导致规划器报错。DELTA 通过在 Prompt 中显式包含 Domain 内容来强化这一点 ^2^。

### 3.4 步骤四：目标分解 (Goal Decomposition) —— 认知的“分而治之”

这是解决长期任务（Long-Horizon Tasks）的核心。对于一个包含 50 个步骤的任务，直接搜索的复杂度是天文数字。DELTA 利用 LLM 的常识将长任务切分为逻辑片段。

* **输入** ：`problem.pddl` 中的全局目标。
* **分解策略** ：LLM 识别子任务之间的依赖关系。
  * *案例* ：在“清洁房屋”任务中，LLM 推理出：“必须先扔垃圾，腾出手来，才能拿拖把；拖完厨房后，拖把脏了，必须先洗拖把，才能去拖客厅。”
  * 这种**因果推理（Causal Reasoning）**是符号规划器在缺乏启发式函数时难以快速发现的，但却是 LLM 的强项。
* **输出** ：子目标序列**$G = \{g_1, g_2,..., g_n\}$**。例如：
  1. **$g_1$**:`(in trash_bin cola_can)`
  2. **$g_2$**:`(clean floor_kitchen)`
  3. **$g_3$**:`(clean mop)`
  4. **$g_4$**:`(clean floor_living_room)`
* **认知科学视角** ：这模仿了人类的高级认知过程——将宏大目标拆解为可执行的里程碑（Milestones），降低了认知负荷 ^1^。

### 3.5 步骤五：自回归子任务规划 (Autoregressive Sub-Task Planning)

最后，系统进入闭环执行阶段，利用经典规划器求解。

* **算法流程** ：
  1. 系统维护当前的世界状态**$S_{current}$**（初始为**$S_0$**）。
  2. 按顺序提取子目标**$g_i$**。
  3. 构建临时 PDDL 问题**$P_i$**：初始状态为**$S_{current}$**，目标为**$g_i$**。
  4. 调用**Fast Downward** 规划器求解**$P_i$**，得到子计划**$\pi_i$**。
  5. 模拟执行**$\pi_i$**（利用 PDDLGym），得到执行后的新状态**$S_{new}$**。
  6. 更新**$S_{current} \leftarrow S_{new}$**，进入下一轮循环。
  7. 将所有**$\pi_i$** 拼接，形成最终的总计划**$\Pi$**。
* **自回归的意义** ：通过每一步更新状态，系统确保了后续规划是基于前一步的实际结果。如果某一步规划失败（例如规划器找不到解），系统可以立即报错并定位到具体的子目标，而不是在整个长序列中盲目排查。
* **规划器选择** ：DELTA 选用了 Fast Downward，这是目前性能最强的经典规划器之一，配置为`seq-opt-lmcut`（序列优化-LM-Cut 启发式），以追求最优解 ^1^。

## 4. 实验评估体系与方法论

为了验证 DELTA 的有效性，研究团队构建了一个全面且严苛的评估体系。

### 4.1 仿真环境与数据集

实验基于 **3D Scene Graph Dataset** ^1^，选取了四个具有代表性的真实室内场景：

1. **Kemblesville** ：小型场景，用于 Prompt 中的 One-shot 示例。
2. **Allensville** ：大型场景，11 个房间，42 个物品。
3. **Parole** ：中型场景，7 个房间，31 个物品。
4. **Shelbiana** ：复杂场景，12 个房间，34 个物品。

这些场景的复杂性在于其非结构化的拓扑连接和丰富的物品种类，真实模拟了服务机器人的工作环境。

### 4.2 任务领域定义 (Task Domains)

实验设计了四类难度递增的任务，涵盖了独立任务和强依赖任务：

1. **PC Assembly (PC 组装)** ：
   * *任务* ：收集分散在房子各处的 6 个电脑配件（CPU, GPU, RAM 等）到同一张桌子上。
   * *特点* ：**独立子任务** 。收集顺序不影响结果，属于简单的旅行商问题变种。
2. **Dining Table Setup (餐桌布置)** ：
   * *任务* ：收集餐具（盘子、叉子、杯子等）并摆放。
   * *特点* ：**独立子任务** 。类似 PC 组装，但物品分布更广。
3. **House Cleaning (房屋清洁)** ：
   * *任务* ：先扔掉所有垃圾（可乐罐、果皮），然后拖地（厨房、客厅），且拖地间隙需清洗拖把，最后回充电桩。
   * *特点* ：**强依赖子任务** 。动作顺序有严格逻辑约束（手被占用就不能拿拖把；拖把脏了不能拖地）。这是对规划器逻辑推理能力的极大考验。
4. **Home Office Setup (办公室布置)** ：
   * *任务* ：搬运家具（桌子、柜子）。柜子内可能有物品，搬运前必须先清空柜子。
   * *特点* ：**强依赖 + 状态约束** 。涉及容器操作和先决条件检查。

### 4.3 基线模型 (Baselines)

为了公平对比，DELTA 与以下四种代表性方法进行了较量：

1. **LLM-As-Planner** ：直接向 GPT-4o 描述环境和目标，要求输出动作序列。这是最原始的用法。
2. **LLM+P** ^6^：将自然语言转为 PDDL，然后直接用规划器求解**完整** 问题。**不进行剪枝和分解** 。
3. **LLM-GenPlan** ^5^：LLM 生成 Python 代码来解决规划问题，利用代码解释器进行逻辑控制。
4. **SayPlan** ^7^：此前的 SOTA 方法。利用语义搜索找到相关子图，然后进行**迭代式重规划** （Iterative Replanning）。即先生成粗略计划，若不可行则根据反馈修正。

## 5. 性能结果深度分析

实验结果展现了 DELTA 在各项指标上的统治级表现。

### 5.1 成功率分析 (Success Rate)

下表总结了各模型在不同领域的成功率（%）：

| **模型**           | **PC Assembly** | **Dining Setup** | **House Cleaning** | **Home Office** | **平均** |
| ------------------------ | --------------------- | ---------------------- | ------------------------ | --------------------- | -------------- |
| **LLM-As-Planner** | 70.0                  | 38.67                  | 0.0                      | 0.0                   | 27.2           |
| **LLM+P**          | 76.0                  | 4.0                    | 0.0                      | 0.0                   | 20.0           |
| **SayPlan**        | 68.67                 | 70.67                  | 54.0                     | 40.0                  | 58.3           |
| **DELTA (GPT-4o)** | **98.0**        | **100.0**        | **80.0**           | **74.67**       | **88.2** |

数据来源：^1^

**深度解读** ：

1. **依赖任务的崩溃** ：LLM-As-Planner 和 LLM+P 在 Cleaning 和 Office 两个强依赖任务中成功率归零。
   * LLM-As-Planner 失败是因为 LLM 无法在大跨度的时间轴上保持逻辑一致性，经常遗漏“洗拖把”或“清空柜子”的步骤。
   * LLM+P 失败是因为未剪枝的场景图引入了数以万计的谓词，导致 Fast Downward 规划器在搜索时**超时（Timeout）** 。这是“维数灾难”的典型体现。
2. **SayPlan 的局限** ：SayPlan 虽然通过重规划在复杂任务中取得了一定成绩（54%），但仍远低于 DELTA。其原因在于重规划本质上是一种“试错法”。在长任务中，错误的累积会导致重规划次数耗尽（实验限制为 4 次）。
3. **DELTA 的稳健性** ：DELTA 在所有任务中均保持了极高的水准。特别是在 Dining 任务中达到 100%，证明了其在处理大规模物体检索与规划上的完美逻辑。即使在最难的 Office 任务中，也将成功率提升了近一倍（40% -> 74.67%）。

### 5.2 计算效率分析 (Computational Efficiency)

除了成功率，规划时间是衡量机器人系统实用性的关键。

* **规划时间对比** ：
  * 在 PC 组装任务中，SayPlan 平均耗时**28.15 秒** ，而 DELTA 仅需**0.02 秒** ^7^。
  * **加速比** ：DELTA 的规划速度比 SayPlan 快了约**1400 倍** ，比无分解的 DELTA 变体快了**3000 倍** 。
* **节点扩展数（Expanded Nodes）** ：
  * 无分解的 DELTA 需要扩展**1,585,185** 个节点才能找到解（或超时）。
  * 分解后的 DELTA 仅需扩展**624** 个节点 ^1^。
  * **原理** ：通过分解，搜索树的深度**$D$** 被切分为**$n$** 个深度为**$D/n$** 的小树。搜索复杂度从**$O(b^D)$** 骤降为**$O(n \cdot b^{D/n})$**。这是算法层面的质变。

### 5.3 消融实验：LLM 的选择至关重要

研究还探讨了不同 LLM 后端对 DELTA 性能的影响。

| **LLM 后端**      | **Cleaning 成功率** | **Office 成功率** |
| ----------------------- | ------------------------- | ----------------------- |
| **Llama-3.1-70B** | 0.0%                      | 0.67%                   |
| **GPT-4-Turbo**   | 32.67%                    | 9.33%                   |
| **GPT-4o**        | **80.0%**           | **74.67%**        |

数据来源：^1^

**关键发现** ：

* **开源模型的差距** ：Llama-3.1 虽然在通用对话上表现优异，但在处理复杂的 PDDL 逻辑生成和长链条因果推理时，表现极其糟糕。这表明 neuro-symbolic planning 对 LLM 的**推理能力（Reasoning Capability）**有极高的门槛要求。
* **模型升级红利** ：从 GPT-4-Turbo 到 GPT-4o，成功率实现了飞跃。这预示着随着 LLM 本身的进化，DELTA 框架的性能还将“免费”提升。

## 6. 比较讨论与前沿技术定位

为了更准确地定位 DELTA 的学术地位，本节将其与 2024-2025 年的最新相关工作进行对比。

### 6.1 DELTA vs. SayPlan：迭代 vs. 分解

SayPlan ^8^ 代表了“反馈修正”流派。它先给出一个粗糙的计划，然后利用模拟器反馈来修补错误。

* **SayPlan 的痛点** ：在长任务中，修正一个错误往往会引发新的错误（Ripple Effect），导致系统陷入修正循环。
* **DELTA 的优势** ：DELTA 采用了“分而治之”的策略。通过在规划前就进行**剪枝** 和**分解** ，它实际上是在构建一个高质量的“问题骨架”。这种前瞻性的结构化处理，比事后的修补要高效得多。

### 6.2 DELTA vs. Context Matters (2025)

2025 年的论文《Context Matters! Relaxing Goals with LLMs》^7^ 指出了 DELTA 的一个潜在弱点：**目标的刚性（Rigidity）** 。

* **批评** ：DELTA 忠实地将用户指令翻译为 PDDL。如果用户要求“扔掉苹果”，但环境中没有垃圾桶，DELTA 会因为无法满足 PDDL 前置条件而直接报错失败。
* **Context Matters 的改进** ：该方法引入了“目标松弛”（Goal Relaxation）机制。当原目标不可行时，LLM 会尝试修改目标（例如：“没有垃圾桶，那我就把苹果放在桌子上”）。
* **对比评价** ：DELTA 专注于**“如何高效地完成可行的任务”**，而 Context Matters 专注于** “如何处理不可行的任务”**。两者侧重点不同，互为补充。

### 6.3 DELTA vs. GraphPlan

GraphPlan ^10^ 批评了 DELTA 的“开环执行”模式。

* **批评** ：DELTA 假设规划出的动作一定能成功执行（Reachability Assumption）。但在真实物理世界中，抓取可能会滑落，移动可能会被阻挡。DELTA 缺乏实时的感知反馈闭环。
* **GraphPlan 的改进** ：引入了基于图的实时验证和重规划机制。
* **回应** ：DELTA 的论文中也承认了这一局限，并将其列为未来工作。目前的 DELTA 更像是一个“大脑皮层”的高级规划器，需要下层的“小脑”控制器来处理具体的执行误差。

## 7. 局限性与潜在风险分析

尽管 DELTA 取得了显著成果，但在实际部署中仍面临以下挑战：

### 7.1 开环执行的脆弱性 (Open-Loop Fragility)

DELTA 目前生成的是静态计划序列。一旦环境发生动态变化（如人移走了目标物体），后续的所有规划都将失效。缺乏实时的感知反馈回路（Closed-Loop Feedback）是其迈向真实家庭服务机器人的最大障碍 ^10^。

### 7.2 对闭源模型的依赖

实验显示 DELTA 高度依赖 GPT-4o 级别的模型。这带来了**成本问题** （API 调用昂贵）、**隐私问题** （家庭数据需上传云端）和**延迟问题** （网络波动影响响应速度）。目前的开源模型（如 Llama-3）尚无法支撑 DELTA 的逻辑需求，限制了其边缘端部署（Edge Deployment）的可能性。

### 7.3 场景图的构建成本

DELTA 假设已经存在一个完美的 3D 场景图。但在实际应用中，构建和维护这样一个包含丰富语义和属性的实时场景图本身就是一个巨大的感知难题。如果感知模块生成的场景图存在噪声（如将猫误识别为狗），DELTA 的规划也将随之出错（Garbage In, Garbage Out）。

## 8. 结论与未来展望

### 8.1 总结

DELTA 框架代表了机器人任务规划领域的一个重要里程碑。它成功地证明了：**通过结构化的环境表征（场景图）和符合认知的任务分解策略，神经符号 AI 能够解决纯学习方法无法处理的长期规划难题。**

其核心价值在于：

1. **极大降低了计算复杂度** ：通过剪枝和分解，将指数级问题降维。
2. **提升了规划的可靠性** ：利用 PDDL 约束消除了 LLM 的物理幻觉。
3. **实现了高效的人机交互** ：用户只需使用自然语言，无需学习复杂的编程指令。

### 8.2 未来方向

未来的研究可能会集中在以下几个方向：

* **闭环 DELTA** ：引入“事件驱动的重规划”（Event-Driven Replanning），在执行过程中实时监控状态，一旦检测到偏差立即触发局部的子目标重规划。
* **多模态增强** ：引入视觉语言模型（VLM），直接从图像中提取场景图信息，实现端到端的感知-规划闭环。
* **本地化部署** ：通过微调（Fine-tuning）小型化的专用 LLM，使其在特定领域达到 GPT-4o 的 PDDL 生成能力，实现隐私保护和低延迟。

综上所述，DELTA 不仅是一个高效的规划算法，更为未来智能机器人的认知架构提供了一个清晰的蓝图——**以语义为图，以逻辑为骨，以语言为魂** 。
