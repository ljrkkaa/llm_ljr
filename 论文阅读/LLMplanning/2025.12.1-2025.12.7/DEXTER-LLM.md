# DEXTER-LLM: Dynamic and Explainable Coordination of Multi-Robot Systems in Unknown Environments via Large Language Models

## 1. 执行摘要

随着机器人技术的飞速发展，多机器人系统（Multi-Robot Systems, MRS）在灾难救援、工业自动化、极地探索等复杂场景中的应用日益广泛。然而，如何在开放且未知的环境中，特别是当环境特征（如受害者位置、火源分布、障碍物类型）动态变化时，实现异构机器人团队的高效、鲁棒且可解释的协调，依然是机器人学领域面临的重大挑战。传统的基于模型的规划方法在处理语义信息和动态约束时显得力不从心，而新兴的基于大型语言模型（LLM）的方法虽然具备强大的语义推理能力，但在长视距规划的逻辑严密性、闭环反馈机制及可解释性方面存在显著缺陷。

在此背景下，北京大学与昆山杜克大学的研究团队于 2025 年提出了 **DEXTER-LLM** （Dextrous Task Execution and Reasoning with Large Language Models）框架。该框架旨在通过一种新颖的混合架构，将 LLM 的开放世界推理能力与基于模型的优化算法（如混合整数规划）相结合，以解决未知环境下的多机器人任务分配（MRTA）问题 ^1^。

## 2. 引言与研究背景

### 2.1 多机器人系统协调的演进与挑战

多机器人系统（MRS）通过多个代理（Agent）的协作，能够完成单个机器人无法完成或效率低下的复杂任务。这种系统的核心在于协调（Coordination），即如何将任务合理地分配给不同的机器人，并在时间与空间上对它们的动作进行调度，以最大化系统的整体效用（如缩短任务完成时间、降低能耗、提高任务成功率）

近年来，大型语言模型（LLM）的爆发为机器人规划带来了新的范式。LLM 蕴含了海量的世界知识和常识推理能力，使其能够理解复杂的自然语言指令，并根据环境描述生成高层的行动计划。诸如 SayCan、VoxPoser 等工作展示了 LLM 在机器人具身智能（Embodied AI）中的潜力 ^4^。

然而，直接利用 LLM 进行多机器人协调也暴露出了严峻的问题：

* **幻觉（Hallucination）：** LLM 可能会生成看似合理但实际上违反物理规律或逻辑的任务序列。
* **开环规划（Open-loop Planning）：** 许多基于 LLM 的方法仅进行一次性规划（One-shot planning），缺乏在执行过程中根据反馈进行实时调整的能力 ^6^。
* **可解释性缺失：** LLM 的决策过程往往是不透明的“黑盒”，这在需要高度可靠性的协作任务中是不可接受的。

### 2.2 DEXTER-LLM 的提出背景

正是在这种背景下，DEXTER-LLM 应运而生。该研究的核心动机是弥合 LLM 的高层推理能力与机器人底层控制的精确性之间的鸿沟。作者团队敏锐地指出，现有的系统要么过于依赖 LLM 而忽视了物理约束的可验证性（如 LLM-GenPlan），要么虽然引入了反馈机制但牺牲了任务调度的最优性（如 COHERENT）^1^。

DEXTER-LLM 的命名寓意着“灵巧的任务执行与推理”（Dextrous Task Execution and Reasoning），其目标是构建一个能够同时满足以下四个关键特性的系统：

1. **动态性（Dynamic）：** 能够适应未知环境中实时出现的任务和特征。
2. **可解释性（Explainable）：** 规划过程对人类操作员透明，便于验证。
3. **最优性（Optimal）：** 在满足约束的前提下，追求任务完成效率的最大化。
4. **可验证性（Verifiable）：** 确保生成的计划符合逻辑时序和物理能力约束。

## 3. DEXTER-LLM 系统架构深度解析

DEXTER-LLM 采用了一种模块化的混合架构，将系统功能解耦为四个紧密协作的模块：任务理解、子任务生成、分配与调度、以及动态适应与验证。这种设计不仅提高了系统的可维护性，还允许针对不同层级的问题采用最适合的解决方法（即用 LLM 处理语义推理，用数学规划处理数值调度）。

### 3.1 模块一：任务理解 (Mission Comprehension)

任务理解模块是人机交互的入口，其核心职责是将非结构化的自然语言指令转化为结构化、无歧义的形式化表达。

#### 3.1.1 自然语言到线性时序逻辑 (NL to LTL)

在多机器人协作中，任务之间往往存在复杂的时序依赖关系（例如，“必须先完成侦查，才能开始救援”或“在灭火的同时不能有人进入区域”）。自然语言虽然表达丰富，但容易产生歧义。为此，DEXTER-LLM 引入了线性时序逻辑（Linear Temporal Logic, LTL）作为中间语言 ^1^。

系统利用 LLM（如 GPT-4 或 DeepSeek）作为翻译器，将用户的自然语言指令转化为 LTL 公式。LTL 能够精确地描述系统的期望行为，包括：

* **安全性（Safety）：****$\square \phi$**（永远保持**$\phi$** 为真，例如“永远不要碰撞”）。
* **活性（Liveness）：****$\diamond \phi$**（最终**$\phi$** 会变为真，例如“最终完成搜救”）。
* **响应性（Response）：****$\square (trigger \rightarrow \diamond action)$**（一旦触发条件满足，最终必须执行动作）。

例如，对于指令“探索整个区域，如果发现火情必须灭火，但在灭火前必须先确保区域内没有人员”，系统可以生成如下 LTL 公式：

$$
\phi = (\square \phi_{exp}) \wedge \square (insp \wedge (fire \rightarrow \diamond ext) \wedge (human \rightarrow \diamond res)) \wedge \dots
$$

这种形式化的转换使得后续的验证和逻辑检查成为可能，这是单纯基于文本生成的规划器所无法比拟的优势。

#### 3.1.2 任务有向无环图 (Task DAG) 的构建

LTL 公式虽然精确，但直接用于任务调度计算复杂度过高。因此，DEXTER-LLM 进一步将 LTL 规范抽象为**任务有向无环图（Task DAG）** 。

这一过程基于非确定性 Büchi 自动机（NBA）的理论。系统从 LTL 公式的接受路径中提取任务的时序约束，构建一个松弛偏序集（Relaxed Partially Ordered Set, R-poset），进而转化为 DAG ^1^。

* **节点（Nodes）：** 代表抽象的高层任务（如“灭火”、“救援”）。
* **边（Edges）：** 代表任务之间的优先关系（Precedence）或互斥关系（Exclusion）。

Task DAG 提供了一个清晰的全局任务视图，既保留了核心的时序逻辑，又便于人类操作员进行快速的视觉检查，确保任务流程的逻辑正确性。

### 3.2 模块二：基于 LLM 的在线子任务生成 (Online Subtask Generation)

这是 DEXTER-LLM 框架中最具创新性的部分之一。与现有的“一次性问答”式 LLM 规划不同，DEXTER-LLM 设计了一个**多阶段引导式推理流水线（Guided Multi-stage Reasoning Pipeline）** ，以解决开放环境下任务分解的复杂性。

#### 3.2.1 第一阶段：上下文分析 (Context Analysis)

在长时间运行的任务中，全局状态信息（Global Info）可能非常庞杂，包含大量的历史数据和无关细节。如果直接将这些信息输入 LLM，不仅会消耗大量的 Token，还容易导致模型注意力分散，产生幻觉。

上下文分析阶段的作用是充当一个“过滤器”。它根据当前的任务目标，从海量的环境感知数据中筛选出相关的关键信息（如“当前任务是灭火，因此水源的位置和灭火器的状态是关键上下文，而远处的无关障碍物可以被忽略”）。这一步确保了 LLM 的推理聚焦于当前的核心矛盾 ^1^。

#### 3.2.2 第二阶段：元策略调整 (Meta Policy Tuning)

这是 DEXTER-LLM 应对“未知环境”的关键机制。在传统规划中，任务分解规则是预定义的（硬编码）。而在 DEXTER-LLM 中，系统维护一个动态的“元策略库”（Meta Policy）。

当环境感知模块检测到新的特征类型（New Feature Type）时（例如，机器人首次在场景中识别出了“沙堆”），LLM 会被触发来分析这个新特征与当前任务的潜在联系，并生成新的策略规则（例如，“如果遇到油类火灾且附近有沙堆，优先使用沙堆覆盖而非水枪”）。这些新生成的规则被更新到元策略库中，指导后续的推理。这种机制赋予了系统类似人类的“举一反三”的学习能力。

#### 3.2.3 第三阶段：子任务向导 (Subtask Guide)

在确立了上下文和策略后，直接生成最终的执行序列仍然容易出错。子任务向导阶段要求 LLM 首先生成一个中间层的任务描述。这一步主要关注任务的逻辑结构，而非具体的执行细节。

LLM 在此阶段会明确任务的复杂依赖关系，例如“为了完成救援，必须先由无人机 A 移除障碍物，同时无人机 B 提供照明”。这种中间表示有助于模型在生成具体指令前理清逻辑链条，减少逻辑错误。

#### 3.2.4 第四阶段：子任务序列生成 (Subtask Sequences)

最后，基于上述所有信息，LLM 输出最终的**分层有向无环图（Layered DAG）** 。在这个图中，每个高层任务节点被展开为一个详细的子任务序列。

* 输出不仅包含动作本身（Action），还包含所需的机器人技能描述（Skill Requirements）、资源需求以及具体的时序依赖。
* 输出格式通常为 JSON，便于后续的数学优化模块读取。

通过这四个阶段的层层递进，DEXTER-LLM 极大地提高了 LLM 推理的准确性、一致性和上下文相关性，有效抑制了幻觉现象。

### 3.3 模块三：最优子任务分配与调度 (Optimal Subtask Assigner and Scheduler)

一旦 LLM 生成了可能的子任务分解方案（Strategy），问题就转化为了一个数学上的资源分配与调度问题。DEXTER-LLM 并没有让 LLM 直接决定“哪个机器人去哪里”，而是采用了基于模型的优化算法，以保证结果的**最优性** 和**可行性** 。

#### 3.3.1 混合整数规划与分支定界 (MIP & BnB)

该模块将子任务分配建模为一个**混合整数规划（Mixed Integer Programming, MIP）**问题。

* **决策变量：** 包括二值变量（决定哪个机器人执行哪个子任务）和连续变量（决定每个子任务的开始时间和结束时间）。
* **目标函数：** 最小化任务的最大完成时间（Makespan），即让整个系统的总耗时最短。
* **约束条件：**
  * **能力约束：** 机器人必须具备执行该子任务所需的技能（如只有具备机械臂的无人机才能执行“抓取”）。
  * **时序约束：** 必须满足 Layered DAG 中定义的先后顺序（Precedence）和互斥关系。
  * **空间约束：** 考虑机器人移动所需的导航时间（基于地图的路径规划估算）。

由于 MIP 是 NP-hard 问题，为了提高求解效率，DEXTER-LLM 结合了**分支定界（Branch-and-Bound, BnB）**搜索算法。

* **搜索树：** 树的每个节点代表一个部分的分配方案。
* **剪枝：** 通过估算当前节点的下界（Lower Bound），如果下界已经超过了当前已知的最优解，则剪掉该分支，从而避免无效计算。

这种“LLM 负责生成策略空间，MIP 负责在空间中搜索最优解”的混合模式，完美结合了人工智能的灵活性与运筹学的严谨性 ^1^。

### 3.4 模块四：动态适应与人机回环验证 (Dynamic Adaptation and Verification)

在开放环境中，变化是唯一的常量。DEXTER-LLM 设计了一套精细的动态适应机制，能够根据不同类型的事件触发不同层级的重规划，从而在响应速度和计算成本之间取得平衡。

#### 3.4.1 多级在线适应机制 (Multi-level Online Adaptation)

系统定义了 7 种触发事件，每种事件对应不同的处理流程 ^1^：

1. **新任务实例（New Task Instance）：** 如探测到新的受害者。仅需触发**分配模块** ，将新任务插入现有计划。
2. **新任务优先级（New Priority Instance）：** 如受害者伤情恶化。触发**任务理解模块** 调整优先级，随后重分配。
3. **新任务类型（New Task Type）：** 如收到全新的上级指令。触发全流程重规划。
4. **新特征类型（New Feature Type）：** 如发现新工具。触发**子任务生成模块** （LLM）更新元策略，探索新解法。
5. **新特征实例（New Feature Instance）：** 如发现新水源位置。触发**分配模块** 更新地图参数。
6. **执行状态更新（Execution Status）：** 监控任务进度，若偏差过大则重调度。
7. **机器人故障（Robot Failure）：** 触发重分配，将故障机器人的任务移交给其他健康机器人。

这种分级处理机制避免了“一有风吹草动就调用 LLM”的低效做法，显著降低了计算开销和响应延迟。实验数据显示，在动态适应过程中，对 LLM 的查询次数减少了 62% ^1^。

#### 3.4.2 人机回环验证 (Human-in-the-loop Verification)

为了增强系统的安全性，DEXTER-LLM 在关键节点引入了人工验证：

* **任务 DAG 验证：** 确认任务优先级的逻辑正确性。
* **分层 DAG 验证：** 确认 LLM 生成的子任务分解策略是否合理（如是否错误地建议用水去灭油火）。
* **局部计划验证：** 确认最终的时间表。

由于 LLM 的输出已经经过了多阶段推理的优化，且系统提供了结构化的图示，操作员的验证过程通常非常迅速。这种机制在保持自动化的同时，保留了人类的最终决定权，这在伦理和安全层面至关重要。

## 4. 实验验证与结果分析

为了验证 DEXTER-LLM 的有效性，研究团队在两个高保真仿真场景中进行了广泛的测试，并与多个 State-of-the-Art (SOTA) 基线方法进行了对比。

### 4.1 实验设置与场景

#### 4.1.1 场景描述

* **场景 I：工业紧急情况（Industrial Emergency）：**
  * **环境：****$40m \times 60m$** 的化工厂区域，包含动态蔓延的火灾、不同伤情的受害者、水库、灭火器仓库等。
  * **机器人编队：** 2 架操作型无人机（具备抓取能力）、2 架灭火无人机、2 辆伤员运输无人车、2 辆多功能灭火无人车。
  * **任务挑战：** 涉及火源扑灭、伤员搜救、资源补给等。任务之间存在强时序依赖（如必须先灭火才能进入救援）。
* **场景 II：北极生态保护（Arctic Protection）：**
  * **环境：****$45m \times 45m$** 的极地环境，包含生物危害区、受困野生动物、冰面裂缝等。
  * **机器人编队：** 4 架多功能无人机、2 辆冰面漫游车、2 辆重载运输车。
  * **任务挑战：** 生态修复、样本采集、动物救助。

#### 4.1.2 对比基线

为了公平评估，实验选取了代表不同技术路线的 SOTA 方法：

1. CMRS ^7^： 端到端的基线方法，直接生成机器人动作计划。
2. SMART-LLM ^8^： 侧重于联盟形成（Coalition Formation）的分层规划方法，但缺乏动态资源约束适应性。
3. RoCo ^4^： 基于多智能体对话（Dialectic）的协作框架，强调通过对话进行协调。
4. COHERENT ^5^： 采用层级架构和反馈循环（Proposal-Execution-Feedback）的方法。
5. LiP-LLM ^10^： 结合线性规划与依赖图的方法，是 DEXTER-LLM 的强力竞争对手。

#### 4.1.3 评价指标

* **成功率 (SR)：** 能够生成有效且可执行计划的试验比例。
* **规划长度效率 (SPL)：** 生成计划的步骤数与真实最优路径长度的比值（越高越好）。
* **完成任务数 (Tasks)：** 在规定时间内完成的任务总量。
* **规划时间 (Time)：** 从环境变化到生成新计划所需的计算时间。

### 4.2 定量结果深度分析

根据论文提供的实验数据 ^1^，DEXTER-LLM 展现出了压倒性的性能优势，特别是在处理复杂任务时。

#### 4.2.1 任务完成率与成功率

在所有测试场景中，DEXTER-LLM 均保持了 **100% 的成功率 (SR)** 。相比之下，基线方法在任务复杂度提升时表现出明显的退化。

* **复合任务（Compound Tasks）表现：** 这是最能体现系统能力的指标。在涉及 3 个以上机器人协作的复合任务中，RoCo 的成功率降至 83% (Scenario I) / 67% (Scenario II)，SMART-LLM 降至 50% / 67%。而 DEXTER-LLM 依然稳如泰山。
* **原因分析：** 复合任务要求严格的时序同步和资源互斥。纯 LLM 方法（如 RoCo）难以在长对话中维持这种严格的逻辑约束，容易导致死锁或冲突。DEXTER-LLM 的 MIP 调度器则能从数学上保证约束的满足。

#### 4.2.2 效率与质量 (SPL & Tasks)

DEXTER-LLM 在任务完成数量上实现了倍级提升。

* **数据对比：** 在场景 I 中，DEXTER-LLM 平均完成了**160.14** 个任务，而表现最好的基线 LiP-LLM 仅完成 57.71 个，COHERENT 完成 62.40 个。这几乎是**3 倍** 的性能提升。
* **路径优化：** DEXTER-LLM 的 SPL 得分高达 0.82，远超 COHERENT 的 0.33 和 SMART-LLM 的 0.10。这表明 DEXTER-LLM 生成的计划不仅“能用”，而且非常“高效”，减少了机器人的无效移动和等待时间。

#### 4.2.3 动态适应的响应性

虽然 DEXTER-LLM 的初始规划时间（约 66秒）长于简单的 CMRS（约 20秒），但其在应对在线变化时表现出了极高的效率。

* **案例分析：** 在实验的时间轴中，当**$t=50s$** 时检测到新的救援站，DEXTER-LLM 仅需触发分配模块，耗时 3秒 即完成了更新，并使后续任务时间减少了 13.5%。
* **LLM 调用优化：** 相比于每次变化都重新查询 LLM 的基线方法，DEXTER-LLM 的多级适应机制显著减少了 LLM 的调用频率（在场景 I 中减少了 81% ^1^），这对于降低 API 成本和规避网络延迟至关重要。

### 4.3 消融实验 (Ablation Study)

研究团队还通过移除不同组件来验证各模块的贡献：

1. **移除元策略 (w/o Meta Policy)：** 性能下降最为剧烈，SPL 从 0.82 跌至 0.47。这证实了在未知环境中，动态生成的元策略是引导 LLM 正确推理的“灵魂”。
2. **更换 LLM 基座：** 将模型从 DeepSeek-V3 换为 GPT-4o 或 Qwen-2.5-max 后，系统性能有进一步提升（SPL 达到 0.85），证明了框架的通用性，且能随大模型能力的进化而进化 ^1^。
3. **移除人工验证：** 成功率从 100% 骤降至 65% (Scenario I)。这凸显了“人机回环”在当前 AI 水平下作为安全最后一道防线的不可或缺性。

## 5. 批判性分析：缺点与局限性

尽管 DEXTER-LLM 在实验中取得了令人瞩目的成绩，展现了混合架构的强大潜力，但作为一个严肃的研究课题，我们必须以批判的眼光审视其在现实世界部署中可能面临的深层次问题和局限性。

### 5.1 集中式架构的可扩展性与单点故障风险

DEXTER-LLM 本质上是一个**集中式（Centralized）**的规划系统。所有的环境感知数据必须汇聚到一个中心节点，由该节点运行 LLM 和 MIP 求解器，再将指令分发给所有机器人。

* **单点故障（Single Point of Failure）：** 这是集中式系统最致命的弱点。在战地、灾区等恶劣环境中，如果中心节点（无论是云端服务器还是本地指挥车）遭受物理损坏或网络攻击，整个机器人集群将瞬间瘫痪，丧失所有协作能力。相比之下，分布式（Decentralized）或基于共识（Consensus-based）的系统（如基于拍卖的算法）通常具有更强的生存能力 ^11^。
* **计算可扩展性瓶颈（Scalability Bottleneck）：** 混合整数规划（MIP）是著名的 NP-Hard 问题 ^13^。虽然论文中使用了分支定界法，且实验规模控制在 10 个机器人以内，但随着机器人数量 (**$N$**) 和任务数量 (**$M$**) 的增加，MIP 的求解空间将呈指数级爆炸。
  * 在**$N=100$** 的大规模集群中，中心节点可能无法在数秒内算出最优解，导致严重的调度延迟。
  * 现有的优化求解器（如 Gurobi）在大规模并发任务下可能面临内存溢出或超时无法收敛的问题。
  * 虽然论文声称“可扩展”，但这主要是在有限实验条件下的观察，缺乏在大规模集群（Swarm）层面的理论或实验验证。

### 5.2 对理想通信环境的过度依赖

DEXTER-LLM 的动态适应机制依赖于**实时、高带宽、低延迟** 的通信链路。

* **带宽消耗：** 为了支持“上下文分析”，机器人可能需要上传高清图像或详细的语义地图给中心节点的 LLM。在许多实际场景（如地下矿井、深海、强电磁干扰区）中，通信带宽极其有限（可能仅有几 Kbps），根本无法支撑这种数据流 ^14^。
* **延迟与丢包：** 论文中的实验是在仿真环境中进行的，假设通信是瞬时且可靠的。然而，在现实中，网络延迟（Latency）和丢包（Packet Loss）是常态。
  * 如果机器人发现新特征（如火情突变）的信息未能及时传达给中心，或者中心的重规划指令在下发途中丢失，机器人将继续执行过时的计划，可能导致灾难性后果（如冲入火场）。
  * 当前的 DEXTER-LLM 架构缺乏针对通信受限环境（Communication-constrained environments）的优化机制，例如在断网情况下的本地降级策略。

### 5.3 LLM 的推理延迟与成本问题

尽管引入了多级适应来减少 LLM 调用，但 LLM 本身的推理特性仍是系统的一个短板。

* **生成延迟（Generation Latency）：** 论文数据显示，子任务生成模块的平均耗时约为**60.1秒** ^1^。对于节奏较慢的任务（如巡检）尚可接受，但在分秒必争的急救或军事对抗中，这一分钟的“思考时间”可能意味着错失战机。相比之下，传统的反应式行为树（Behavior Trees）响应速度通常在毫秒级。
* **成本与能耗：** 持续运行高性能 LLM（如 GPT-4o 或 Qwen-max）需要昂贵的 API 费用或庞大的本地算力支持（如多张 H100 GPU）。这使得该系统难以部署在低成本、低功耗的边缘设备上。
* **幻觉风险残留：** 尽管有多阶段推理和人工验证，LLM 的幻觉问题无法从根本上消除。在极度罕见或反直觉的场景（Out-of-Distribution）中，元策略可能失效，LLM 可能生成似是而非的错误建议。过分依赖人工验证则引入了人为失误（Human Error）的风险，尤其是在操作员疲劳或高压状态下。

### 5.4 仿真与现实的鸿沟 (Sim-to-Real Gap)

论文的验证完全基于数字仿真，这掩盖了许多物理世界的复杂性。

* **感知假设过于完美：** 实验假设系统能准确识别“新特征类型”（例如，准确地将一个未知物体分类为“灭火沙堆”）。在现实中，开放环境下的物体识别极其困难，光照、遮挡、污损都会导致感知失败。如果感知模块输出了错误的信息（Object Detection Failure），LLM 的推理基础就会崩塌（Garbage In, Garbage Out）。
* **执行的不确定性：** MIP 调度生成的是精确到秒的时间表。然而，现实中的机器人移动受地面摩擦、风阻、机械磨损等影响，很难精确执行。
  * 如果一个机器人比计划晚到了 5 秒，是否需要触发全局重规划？
  * 如果频繁触发重规划，系统可能陷入“计算-执行-再计算”的死循环（Thrashing），导致机器人停滞不前。
  * 目前的框架缺乏底层的鲁棒控制策略来吸收这些微小的执行误差。

### 5.5 物理交互建模的缺失

DEXTER-LLM 主要关注高层的任务逻辑（Task Level），而对底层的物理交互（Physical Interaction）简化处理。

* 在狭窄空间中，多台机器人可能会发生物理拥堵（Traffic Congestion），简单的路径规划估算无法反映这种动态的物理干涉。
* 对于需要紧密物理耦合的任务（如两台无人机协同搬运一个重物），仅靠高层的 DAG 和时间表是不够的，还需要底层的力位混合控制和实时通信，但这超出了 DEXTER-LLM 的规划范畴。

## 6. 结论与未来展望

DEXTER-LLM 是一项具有开创性意义的研究工作。它成功地在 LLM 的泛化能力与传统优化方法的严谨性之间架起了一座桥梁，提出了一种在未知环境下实现动态、可解释且高效的多机器人协调的新范式。其“多阶段推理”不仅提升了 LLM 的可用性，更通过“元策略”机制赋予了系统类似人类的学习适应能力；其“混合整数规划”后端则确保了在复杂约束下的调度最优性。实验数据无可辩驳地证明了其在处理异构协作任务时相对于现有 SOTA 方法的巨大优势。

然而，要将 DEXTER-LLM 从实验室推向真实的复杂世界，仍需跨越巨大的工程鸿沟。未来的研究应当聚焦于以下几个方向：

1. **去中心化与边缘计算：** 研究如何将中央 LLM 的高层决策“蒸馏”（Distill）为轻量级的本地策略，或者利用边缘侧的小型语言模型（SLM）实现分布式的协作规划，以降低对中心节点和通信带宽的依赖。
2. **鲁棒性与概率规划：** 引入概率模型来处理感知和执行的不确定性，而非依赖确定性的 MIP 求解。例如，使用机会约束规划（Chance-Constrained Programming）来容忍一定程度的执行误差。
3. **分层计算架构优化：** 探索如何将耗时的 LLM 推理与实时的反应式控制更好地解耦。例如，LLM 只负责生成长期的战略目标（Strategic Goals），而将战术层面的避障和即时协作交给传统的、响应更快的控制算法。
4. **通信感知规划（Communication-Aware Planning）：** 将通信质量纳入规划约束中，使机器人能够在通信受限时自动切换到自主模式，或主动移动到信号良好的区域进行数据同步 ^14^。

综上所述，DEXTER-LLM 为具身智能集群（Embodied AI Swarms）的发展指明了一个极具前景的方向，即“神经符号人工智能”（Neuro-symbolic AI）在机器人领域的深度应用。尽管仍有局限，但它标志着我们向构建真正智能、自主、适应性强的机器人团队迈出了坚实的一步。
